# Link-exchange outreach

Read this reference when the user supplies a website and wants to explore a reciprocal link arrangement.

## Inventory the target site

Start from the supplied domain and confirm its canonical URL. Inspect the homepage, blog or resource index, relevant navigation, and contact page. Look for a sitemap in the robots file, common sitemap URLs, or the site's own links. If a sitemap is unavailable, use a Google-capable search or another available search source with queries such as:

```text
site:example.com TOPIC
site:example.com (guide OR research OR checklist OR tools) TOPIC
```

Record the actual search source. Use the target site's own pages as evidence, not search snippets alone. Collect a useful set of existing editorial URLs and inspect the pages most likely to answer the user's topics. Note each page's title, H1, slug, main intent, relevant passage, and current external links. A page that is inaccessible, noindexed, purely commercial, or made only for links is a weak exchange candidate.

When the target site's topic is broad, derive a small set of search terms from its titles, H1s, headings, and the user's verified focus topics. Add those terms to the `site:` queries instead of searching the whole domain indiscriminately.

If an Ahrefs, Semrush, DataForSEO, or equivalent provider is available, use its traffic, authority, referring-domain, and ranking-keyword data as directional context. Keep the provider, date, country, device, database, and domain scope beside the values. Ranking overlap can help prioritize pages, but it cannot replace page-level editorial fit or prove that an exchange is safe.

## Inventory the user's content

Read the user's blog index or sitemap. Use slugs as keyword hints, then open candidate pages and verify their topic, intent, evidence, and current link status. Infer the target keyword from the page title, H1, headings, and confirmed SEO context. Never invent a keyword or claim that a page covers a topic it does not cover.

## Match page pairs

For each promising target page, look for one or more existing user pages that genuinely improve that page for its readers. Suggest multiple options only when the pages or angles are materially different. For every option, record:

- target page URL and the exact passage or section where the link could fit;
- user's page URL and what useful evidence, process, example, or explanation it adds;
- the target page's inferred topic and intent;
- one or more natural anchor choices, with the least forced option first;
- why the link is editorially useful and whether a similar link already exists;
- confidence and any unresolved issue such as a missing passage, existing link, or unclear policy.

Prefer in-content links that help the reader continue their research. Skip footer, sidebar, sitewide, comment, author-bio, or unrelated promotional placements. Do not require an exact-match anchor, promise ranking gains, or recommend a link only because a competitor has one. A competitor link is a research clue, not evidence that the publisher owes a reciprocal link.

Prioritize a small number of page-specific editorial links. Mark a proposal `uncertain` when it depends on sitewide links, exact-match anchors, unrelated pages, or a large reciprocal network.

## Ask about the reverse direction

First present the target-to-user opportunities. Then ask whether the user also wants a user-to-target suggestion. Do not research or promise the reverse placement before the user opts in.

If the user opts in, inspect the user's relevant pages and find an existing page where a link to the target site would add real value. Return the target URL, insertion context, natural anchor options, and reader benefit. Treat both directions as proposals until the user approves the final message and any terms.

## Prepare the proposal

Find the target site's published contact route. Draft a short message that names the relevant target page and section, proposes the user's page and a natural link, and explains the reader benefit. If the reverse direction was approved for research, present it as an optional counterpart rather than a guaranteed trade.

Show any fee, sponsored or nofollow attribute, exclusivity term, account requirement, content change, or request to alter an existing link. Pause for the user before accepting a commercial or editorial term. Use [submission.md](submission.md) for the final authorization and sending steps.

## Completion criterion

The link-exchange package is complete when it contains the inspected target-site scope, evidence-backed target-to-user page pairings with placement and anchor options, a contact route or blocker, and an approval-ready proposal. If the user has not opted into the reverse direction, ask that question explicitly and leave that part unresearched.
